# Расширение парсера

## Новый тег существующей версии

1. Сверить форму, аргументы, режим тела и контекст со спецификацией DSL.
2. Сначала добавить табличные и пограничные тесты. Для нового поведения тест обязан дать ожидаемый RED.
3. Если подходят существующие схемы, добавить только запись в `internal/registry/v1_1.go`.
4. Если формат новый, добавить минимальный именованный обработчик в подходящую группу `internal/handlers`, не создавая пакет на тег.
5. Общую токенизацию, экранирование, границы и разделители оставить соответственно в `scan`, `structure` и общих обработчиках.
6. Обновить таблицу [grammar-coverage.md](grammar-coverage.md) и при необходимости каталог [diagnostics.md](diagnostics.md).
7. Выполнить все команды проверки из корневого [README](../README.md).

## Новая версия существующего тега

1. Сначала зафиксировать тестами отличия версии и отсутствие регрессии DSL 1.1.
2. Создать отдельный неизменяемый набор записей версии и зарегистрировать его в `registry.ForVersion`.
3. Переиспользовать обработчик, если его контракт совпадает; иначе добавить отдельный `HandlerID` и локальный обработчик. Не изменять семантику обработчиков других версий.
4. Проверить, что `Registry` возвращает независимые копии и выбор версии не использует изменяемого глобального состояния.
5. Обновить документацию только после GREEN.

Изменение поведения всегда следует циклу RED → минимальная реализация → GREEN. Запрещено добавлять публичный тип или интерфейс только ради будущего расширения.
